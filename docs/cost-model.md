# 成本模型与口径说明

这份文档回答一个核心问题：**同一批单据，为什么应该算出这个数？**

ERP 成本模块最容易出问题的地方不是代码，而是口径。口径不一致时，系统能算出数，但财务不认、业务不服、差异解释不了。所以这里把每个假设写清楚，代码只是这些规则的实现。

---

## 1. 适用范围

| 维度 | 本期口径 |
|---|---|
| 行业 | 组装型（离散）制造业：多层级 BOM、工单组织生产、半成品独立入库 |
| 成本方法 | 分批法（按工单归集）+ 逐步结转分步法（半成品随实物逐级结转） |
| 成本项目 | 直接材料、直接人工、制造费用 |
| 期间 | 单公司、单会计期间、期初在产为 0 |
| 货币 | 人民币，金额 2 位小数，单价/费率 4 位小数，数量 4 位小数 |

不适用范围：流程型（联产品/副产品）、项目型（按项目归集）、标准成本与实际成本并行的两套账。

---

## 2. 基础口径

### 2.1 损耗率

BOM 的 `scrap_rate` 表示「为产出 1 单位父项，除净用量外还要多投的比例」：

```text
单位标准用量 = 单位净用量 × (1 + 损耗率)
```

例：壶身组件用不锈钢板 0.8 kg，冲压损耗 2%，则标准用量 `0.8 × 1.02 = 0.816 kg`。

### 2.2 半成品的「完全成本」

自制件的标准成本不是只有材料，而是**材料 + 本工序人工 + 本工序制造费用**，逐层向上滚：

```text
标准成本(自制件) = Σ[单位标准用量 × 子件标准成本] + Σ[工序标准工时 × (标准人工费率 + 标准制造费用分配率)]
标准成本(外购件) = 标准采购价
```

这是本项目一个关键决策。如果上层只滚材料、不滚加工费，成品的「标准材料成本」与「实际领用半成品的结转价」就会差一个加工费，差异分析里会出现一笔永远解释不清的口径差。

以演示数据为例：

```text
SF-BODY = 0.816×12 + 6.5 + 4×0.05 + 0.05×(28+30) = 16.492 + 2.9 = 19.392
FG-KT100 = 19.392 + 17.882 + 4.2 + 1.5 + 0.08×58 + 0.02×62 = 48.854
```

### 2.3 约当产量

```text
材料约当量 = 完工数量 + 报废数量 + 在产数量 × 投料程度
加工约当量 = 完工数量 + 报废数量 + 在产数量 × 完工程度
```

装配型企业的材料通常在开工时一次性投入，`material_completion = 1`；人工与制造费用随进度发生，用 `wip_progress` 折算。

**标准用量与标准工时也必须按约当量计算**，否则「在产越多、差异越难看」——那不是成本失控，是口径错误。

## 3. 归集

| 成本项目 | 来源单据 | 归集规则 |
|---|---|---|
| 直接材料 | 领料单 / 退料单 | 按工单汇总：`Σ(数量 × 实际单价)`，退料为负数自动冲减 |
| 直接人工 | 报工单 | `Σ(工时 × 实际费率)`，未填实际费率时取成本中心标准费率 |
| 制造费用 | 费用发生额 | 先按成本中心汇总成费用池，不直接进工单 |

制造费用之所以不能直接进工单，是因为它服务于整个成本中心：水电、折旧、车间管理薪酬无法判断「属于哪一台热水壶」。必须先池化，再按动因分配。

---

## 4. 分配

### 4.1 分配率

```text
实际分配率 = 成本中心费用池 / 该中心本期动因总量
某工单应承担 = 该工单动因量 × 实际分配率
```

默认动因是**实际人工工时**（来自报工单）。换成机器工时或产量，只需替换动因的构造方式，分配算法不变。

### 4.2 尾差

四舍五入后各工单分摊额之和可能比费用池少或多几分钱。本项目用**最大余额法**：

1. 按权重算出理论分摊额，向下取整到分；
2. 计算剩余的分钱；
3. 按小数部分从大到小，每个工单补 1 分，直到分完。

演示数据：总装车间费用池 3,900 元，工时 38 / 27 / 40 / 14（合计 119）：

| 工单 | 工时 | 分摊额 |
|---|---:|---:|
| PO-1001 | 38 | 1,245.38 |
| PO-1002 | 27 | 884.87 |
| PO-1003 | 40 | 1,310.93 |
| PO-1004 | 14 | 458.82 |
| 合计 | 119 | **3,900.00** |

### 4.3 未分配余额

有费用池、但没有工单消耗该中心动因时（演示中的设备维护组：260 元），这笔钱不会消失，也不会被摊进其他工单，而是作为**未分配制造费用**挂账，并触发 `OH-UNALLOCATED` 严重预警。

这是成本控制里最典型的漏洞：费用真实发生了，却没有人对它负责。真实 ERP 会用交互分配法把辅助部门费用先分给生产部门，本项目留到 M7。

## 5. 半成品逐级结转

### 5.1 计算顺序

工单按产出物在 BOM 中的层级**升序**计算（叶子优先）：外购件 0 层，半成品 1 层，成品 2 层。这样下游工单领用半成品时，上游的实际成本已经确定。

```text
SF-BODY(1) ─┐
SF-BASE(1) ─┼─→ FG-KT100(2)
```

### 5.2 结转单价

```text
半成品单位成本 = 本期该半成品所有完工工单的良品入库成本合计 / 完工数量合计
下游领用金额   = 领用数量 × 半成品单位成本
```

采用**全月一次加权平均**：同一半成品本期有多个工单时，下游统一按加权平均价领用，避免同一批成品里混着不同单价。

### 5.3 没有实际成本时

若下游领用了某半成品，但本期没有它的完工入库（例如期初库存、或工单尚未完工），系统退回**标准成本**结转，并在工单备注与预警里明确标注 `TRANSFER-STD`。金额按标准价冲平，不制造虚假价差。

## 6. 完工与在产

设 `完工 = 良品数量`，`报废 = 废品数量`，`在产 = 计划 − 完工 − 报废`：

```text
单位材料成本 = 材料总成本 / 材料约当量
单位加工成本 = (人工 + 制造费用) / 加工约当量
单位完全成本 = 单位材料成本 + 单位加工成本

完工成本（含废品） = 单位完全成本 × (完工 + 报废)
废品损失           = 单位完全成本 × 报废
期末在产成本       = 工单总成本 − 完工成本
```

**成本守恒**：`完工入库 + 期末在产 ≡ 工单总成本`，由测试逐单断言。

废品按已完工处理（假设报废发生在完工检验），其损失**由合格品负担**——这是教材口径：废品损失计入当月合格品成本，不单设支出科目。因此：

- 完工入库成本 = 完工成本（含废品），即良品与废品共同构成；
- `废品损失` 单独列示，只用于考核与分析，不改变入账金额；
- 良品单位成本 = 完工入库成本 / 完工数量，废品越多，单位成本越高。

不区分料废 / 工废，也不做残值回收。

### 6.1 期初在产（跨期工单）

跨期工单在下一期的起点是「期初在产」：上期末按成本项目沉淀下来的余额。

```text
总成本 = 期初在产（材料 + 人工 + 制造费用） + 本期归集
材料约当量 = 本期完工 + 报废 + 期末在产 × 投料程度      ← 不含期初
加工约当量 = 本期完工 + 报废 + 期末在产 × 完工程度      ← 不含期初
单位成本 = 总成本 / 约当量
```

**期初数量已经包含在「完工」或「期末在产」里，不能再加进分母**，否则同一批在产品的成本与产量各算一次，单位成本会被系统性低估。

差异则要换口径，因为期初成本没有对应的本期用量：

```text
本期增量约当量 = 完工 + 期末在产约当 − 期初在产约当
期初沉淀差异   = 期初在产 − 期初标准（按上期末进度折算）
本期增量差异   = 本期发生 − 本期增量标准（六项分解）
工单总差异     = 期初沉淀差异 + 本期增量差异
```

演示：PO-1004 在 10 月末有 47 件在产（材料 100%、加工 40%），期初成本 2,212.84；11 月完工：

```text
总成本 2,212.84 + 235.97 = 2,448.81，单位 52.10（标准 48.85）
差异 152.67 = 期初沉淀 82.52 + 本期 70.15
```

其中 82.52 是 10 月超支带过来的，本期只占 70.15——不拆开就会把上月的问题算到这个月头上。

### 6.2 总账余额链

关账时不仅结转在产，还要把全部科目期末余额写成下期的期初余额，并校验：

```text
5001 期初 = Σ 期初在产成本
期初余额借贷合计 = 0
```

否则下一期的试算平衡从第一天就是断的。演示里 10 月关账后 5001 期初 2,345.47，11 月完工结转 9,596.44，期末 312.63，正好是 12 月的期初。

## 7. 标准成本与差异

### 7.1 差异六项分解

| 差异 | 公式 | 含义 |
|---|---|---|
| 材料价差 | `(实际单价 − 标准单价) × 实际用量` | 采购价格变化 |
| 材料量差 | `(实际用量 − 标准用量) × 标准单价` | 超耗 / 节约 |
| 人工工资率差异 | `(实际工资率 − 标准工资率) × 实际工时` | 加班、工资调整、人员结构 |
| 人工效率差异 | `(实际工时 − 标准工时) × 标准工资率` | 效率高低 |
| 费用耗费差异 | `实际费用 − 标准分配率 × 实际工时` | 费用本身超支 |
| 费用效率差异 | `(实际工时 − 标准工时) × 标准分配率` | 工时变化带来的费用变化 |

其中：

```text
标准用量 = 单位标准用量（含损耗）× 材料约当量
标准工时 = 单位标准工时 × 加工约当量
```

六项之和等于 `实际总成本 − 标准总成本`（各分项独立取整到分，可能有 1 分尾差）。

### 7.2 演示：PO-1001 的 953.48 元差异

```text
材料价差 388.50   ← 不锈钢 12.00→12.30、温控器 6.50→6.80
材料量差 285.60   ← 不锈钢标准 571.2 kg，实际净领 595 kg
人工效率  84.00   ← 标准 35 h，实际 38 h
费用耗费 105.38   ← 车间费用 3,600 → 3,900
费用效率  90.00   ← 多出的 3 小时带出的费用
```

差异不是「一个数」，而是一组可以追到原因的解释。成本控制系统的价值就在这里：把总差异还原成**责任归属**。

### 7.3 差异的传导

成品领用半成品时按实际成本结转，因此上游超支会进入下游的材料价差：

```text
PO-1001 壶身组件单位成本 20.9034，标准 19.3920
  → PO-1003 领用 450 件，形成材料价差 (20.9034 − 19.3920) × 450 = 680.13
```

也就是说，成品 5.08% 的超支里，有一大半不是总装车间造成的，而是壶身组件工单传下来的。**成本还原**（把成品差异拆回半成品/材料/工序）是 M4 的内容。

## 8. 控制规则

| 规则 | 触发条件 | 级别 | 默认容差 |
|---|---|---|---|
| `MAT-OVERUSE` | 实际用量 > 标准用量 ×(1+容差) | 警告 | 2% |
| `ORDER-OVERSPEND` | 工单差异率 > 容差（超 2 倍容差升严重） | 警告/严重 | 3% |
| `SCRAP-RATE` | 报废率 > 容差 | 警告 | 2% |
| `OH-UNALLOCATED` | 费用池 > 0 且无动因 | 严重 | — |
| `OH-OVERBUDGET` | 实际费用 > 预算 ×(1+容差) | 警告 | 0% |
| `TRANSFER-STD` | 半成品按标准价结转 | 提示 | — |
| `NO-STANDARD` | 无标准成本却有实际成本 | 警告 | — |

阈值全部来自数据集的 `params`，可用命令行覆盖，不需要改代码。

## 9. 记账与结账

成本计算单只是管理口径，进得了总账才算 ERP 模块。凭证规则如下：

| 业务 | 借方 | 贷方 |
|---|---|---|
| 材料领用 | 5001 生产成本 | 1403 原材料 / 1406 自制半成品 |
| 直接人工 | 5001 生产成本 | 2211 应付职工薪酬 |
| 制造费用发生 | 5101 制造费用 | 1002 银行存款 / 1602 累计折旧 / 2211 应付职工薪酬 |
| 制造费用分配 | 5001 生产成本 | 5101 制造费用 |
| 完工入库 | 1405 库存商品 / 1406 自制半成品 | 5001 生产成本 |
| 未分配费用结转 | 6602 管理费用 | 5101 制造费用 |

这些分录保证了一个恒等式：

```text
5001 期末余额 = 本期归集总成本 − 完工入库成本 = 期末在产品成本
```

结账检查把这条恒等式当成硬约束。任何一项不满足都阻断结账：

| 检查 | 阻断 | 说明 |
|---|---|---|
| `LEDGER-BALANCED` | 是 | 每张凭证借贷相等、全账借贷相等 |
| `OPENING-BALANCED` | 是 | 期初余额借贷平衡 |
| `COST-CONSERVATION` | 是 | 生产成本余额 = 期末在产 |
| `TRIAL-BALANCE` | 是 | 期末余额合计为 0 |
| `OH-UNALLOCATED` | 默认否 / 严格模式是 | 未分配制造费用默认转管理费用，严格模式禁止结账 |
| `WIP-CARRIED`、`SCRAP-RATE` | 否 | 提示与预警 |

## 10. 已知简化

写清楚边界，比假装完备更有用：

1. 单期间、单公司，期初在产为 0（M3 补多期间与期初）。
2. 制造费用只有一层分配，未做辅助部门交互分配（设备维护组的 260 元因此挂账）。
3. 联产品、副产品、返工、委外加工未支持。
4. 废品不区分料废/工废，不计算残值。
5. 标准成本无版本管理，改 BOM 直接改变标准。
6. 结账只做检查与未分配费用结转，未做期间锁定、反结账与重算审计（M3）。
7. 数量精度 4 位小数，超大数量（>10^9）未做专项处理。

## 11. 数据结构

数据集为单个 JSON，顶层字段：

```text
company          公司名称
period           会计期间，如 "2026-10"
cost_centers     成本中心：code/name/labor_rate/overhead_budget/budget_hours
materials        物料：code/name/mtype(RAW|SEMI|FINISHED)/uom/standard_price
bom              BOM：parent/component/qty_per/scrap_rate
routing          工艺路线：product/seq/cost_center/std_hours
orders           工单：order_no/product/qty_planned/qty_completed/qty_scrapped/wip_progress/material_completion
issues           领料：doc_no/order_no/material/qty/unit_price
labor            报工：doc_no/order_no/cost_center/hours/hourly_rate(可选)
overhead         制造费用：cost_center/expense_type/amount
params           控制阈值
opening_balances 期初余额：debit/credit 两个对象，科目代码 → 金额
```

载入时统一校验：物料/成本中心存在、工单不超产、用量与损耗率合法、BOM 无环、期初余额借贷平衡。脏数据在计算前就会报错，而不是算出一张错单。
