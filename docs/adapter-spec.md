# 适配器规范：从 ERP 导出到规范事实

这份文档定义 **ERP 导出 → 规范事实 → 归因报告** 之间的契约。

一句话：**适配器只翻译，不计算。** 金额怎么算由核心引擎负责；适配器负责把
SAP / 用友 / 金蝶的列名、代码值、日期格式翻译成固定结构，并做完整性校验。

---

## 1. 为什么先定契约，而不是先找数据

没有真实导出数据时，最容易走错的路是「等拿到数据再写 adapter」。实际上：

- 厂商的**报表列定义是公开的**（SAP CO-PC 成本分析、用友 U8 生产订单/领料单、
  金蝶云星空引出模板），列名和含义可以直接从文档与演示账套里确认；
- adapter 的难点是**字段映射与代码值映射**，不是数值分布；
- 只要契约稳定，真实数据到了只需要改 `config_templates/adapters/*.yaml`，不改代码。

所以先有契约与合成导出，真实数据只影响映射文件。

---

## 2. 规范事实（Canonical Fact）

归因层只认这一种结构（代码见 `costcontrol/facts.py`）：

| 字段 | 必填 | 含义 | 来源示例 |
|---|---|---|---|
| `fact_id` | 是 | 事实编号 | `VF-2026-10-001` |
| `period` | 是 | 会计期间 | `2026-10` |
| `cost_element` | 是 | 差异要素编码 | `MAT-QTY-VAR` |
| `amount` | 是 | 差异金额（正=超支，负=节约） | `285.60` |
| `order_no` | 是 | 生产订单 | `PO-1001` |
| `product` | 是 | 产品 | `SF-BODY` |
| `material` | 材料类必填 | 物料 | `RM-SS304` |
| `material_type` | 材料类必填 | `RAW` / `SEMI` / `FINISHED` | `RAW` |
| `cost_center` | 人工/费用类必填 | 成本中心 | `CC-ASM` |
| `work_center` | 可选 | 工作中心/产线 | `WC-ASM-1` |
| `operation` | 可选 | 工序 | `10` |
| `supplier` | 价差建议 | 供应商 | `宁波金属材料` |
| `evidence` | 是 | 判断依据键值对 | `qty=595, std_qty=571.2` |

`evidence` 是归因规则声明「需要哪些证据」的依据。缺证据不会导致归因失败，
但会把置信度从「高」降到「中」。

---

## 3. 差异要素编码

| 编码 | 中文 | 与 SAP CO-PC 的对应 |
|---|---|---|
| `MAT-PRICE-VAR` | 材料价差 | 投入价差（PPV） |
| `MAT-QTY-VAR` | 材料量差 | 投入量差 |
| `LABOR-RATE-VAR` | 人工工资率差异 | 资源价格差异 |
| `LABOR-EFF-VAR` | 人工效率差异 | 资源利用差异 |
| `OH-SPEND-VAR` | 制造费用耗费差异 | 剩余差异（部分） |
| `OH-EFF-VAR` | 制造费用效率差异 | 资源利用差异（费用部分） |

注意：SAP 的「产出价差」「批量差异」在本项目六项里**没有一一对应**，映射表
必须显式标注「无对应」，不要硬凑（见 `docs/variance-mapping.md`，待补）。

半成品的 `MAT-PRICE-VAR` 不是采购价差，而是上游工单转入的成本差异，
`evidence.upstream_orders` 会记录来源订单，责任映射应单独处理。

---

## 4. 适配器职责

| 做 | 不做 |
|---|---|
| 按映射读文件、识别编码（UTF-8 BOM / GB18030） | 计算任何成本或差异 |
| 代码值映射（外购→RAW、完工→COMPLETED） | 修改 ERP 数据 |
| 日期/数值规范化 | 生成凭证或调账 |
| 缺列、缺文件、类型错误时明确报错 | 猜测缺失字段的业务含义 |
| 输出 `Dataset` 或 `VarianceFact` | 决定责任主体（那是归因层） |

## 5. 映射文件结构

一个厂商一个 YAML，放在 `config_templates/adapters/`：

```yaml
vendor: yonyou_u8
files:
  materials: 01-物料主数据.csv
  orders: 05-生产订单.csv
  # ...
columns:
  materials:
    code: 物料编码
    name: 物料名称
    mtype: 物料类型
    standard_price: 标准价
values:
  mtype:
    外购: RAW
    自制: SEMI
    成品: FINISHED
```

- `columns`：**规范字段 → ERP 列名**（导出时反向写表头，导入时按表头取值）；
- `values`：**ERP 代码值 → 规范值**；
- 换厂商只新增一个 YAML，代码零改动。

---

## 6. 接入真实数据的步骤

1. **拿到导出文件（或只是表头）**：Excel 另存为 CSV，确认编码（UTF-8 或 GBK）。
2. **复制模板**：`config_templates/adapters/yonyou_u8.yaml` → `你的厂商.yaml`。
3. **填 `files` 与 `columns`**：先保证字段名对得上，值映射可以后补。
4. **试读**：

   ```bash
   python -m costcontrol.cli --csv <导出目录> --adapter <你的映射.yaml> --detail
   ```

5. **与 ERP 对数**：挑一张工单，比对总成本、材料/人工/费用三项；差异应在
   舍入范围内。对不上先查口径（约当量、在产、结转价），不要急着调 adapter。
6. **跑归因**：

   ```bash
   python -m costcontrol.cli --csv <导出目录> --adapter <映射.yaml> --attribute
   ```

7. **补组织映射**：在业务 Sense 的 `org` 里补成本中心名称、产线、供应商，
   置信度才会从「中」升到「高」。

## 7. 最小数据要求

| 文件 | 最小列 | 缺了会怎样 |
|---|---|---|
| 物料主数据 | 编码、名称、类型、单位、标准价 | 无法算标准成本 |
| BOM | 父项、子项、用量 | 无法卷算材料标准 |
| 工艺路线 | 产品、工序、成本中心、标准工时 | 无法算人工/费用标准 |
| 生产订单 | 工单号、产品、计划/完工/报废、在产进度 | 无法拆完工与在产 |
| 领料单 | 工单、物料、数量、单价 | 材料差异缺失 |
| 报工单 | 工单、成本中心、工时 | 人工与费用动因缺失 |
| 制造费用 | 成本中心、费用类型、金额 | 费用差异缺失 |
| 期初余额/在产 | 科目/工单、金额/进度 | 跨期工单成本断裂 |

可选但强烈建议：供应商（价差归因）、工作中心/产线（效率归因）、工序（细粒度归因）。

---

## 8. 缺失维度怎么办

不猜。缺失维度会让归因置信度下降并转人工：

- 价差缺供应商 → 仍归采购部，置信度「中」，报告标注「缺 supplier」；
- 效率差异缺工作中心 → 归到成本中心，置信度「中」；
- 规则要求的证据全缺 → 转 fallback（成本会计复核），置信度「低」。

---

## 9. 没有真实数据时怎么开发

| 方式 | 说明 | 适合 |
|---|---|---|
| 合成导出 | `--export-csv` 把演示数据写成 ERP 形态的 CSV；`--csv` 读回 | 开发、测试、演示 |
| 厂商试用/演示账套 | 用友 T+、金蝶云星空、SAP 试用环境里自带演示公司，可自行导出 | 验证列名与代码值 |
| 开源 ERP demo 数据 | Odoo / ERPNext / InvenTree 的演示数据包含 BOM、工单、库存移动 | 验证制造单据结构 |
| 脱敏样本 | 请实施顾问/会计朋友提供「表头 + 5 行」，签 NDA | 最终验收 |

合成数据能验证**流程与契约**，不能验证**字段覆盖率**；真实数据到手后，
第一件事是把 `--csv` 读一遍，看哪些列没被映射、哪些值是空的。

---

## 10. 验收标准

1. **往返一致**：演示数据 → `--export-csv` → `--csv` → 成本总额与差异逐单一致；
2. **对数通过**：真实导出重算的总成本与 ERP 成本报表差异在舍入范围内；
3. **归因可解释**：每条差异都能指出成本要素、责任主体、证据与置信度；
4. **降级明确**：缺维度/缺规则时能明确转人工，不产生虚假的高置信归因。
