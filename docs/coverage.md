# 导出覆盖率检查：先判断数据能做什么

拿到一份 ERP 导出，最容易犯的错是直接跑分析，然后得出一个看起来成立、其实口径不通的结论。
覆盖率检查只回答三件事：

1. 这些文件是什么类型、字段全不全；
2. 哪些分析能力可用、哪些不可用、缺什么；
3. 表与表之间、BOM 与领料之间对不对得上。

## 1. 识别方式

不依赖文件名，按**表头**匹配已知单据类型：

| 类型 | 识别列（节选） |
|---|---|
| SAP 成本构成 | 成本组件、2025年均值_元每件、占比_综合 |
| SAP 存货明细 | 会计年度期间、科目编码、期初余额_万元 |
| 金蝶成本计算单 | 工单编号、完工数量、直接材料_元、单位成本_元 |
| 金蝶成本还原 | 成本项目、还原前金额_万元、半成品还原金额_万元 |
| 用友完工日报 | 会计期间、完工数量、净产量、实际工时 |
| 用友废品回收 | 季度、废品重量_kg、回收单价_元每kg |
| BOM | 父项物料编码、子项物料编码、单位用量、损耗率 |
| 领料明细 | 工单编号、物料编码、领用数量、金额_元 |
| 报工明细 | 工单编号、工序、成本中心、实际工时、人工成本_元 |
| 物料主数据 | 物料编码、标准价_元 |
| 工艺路线 | 产品编码、工序、标准工时_分钟每件 |
| 生产订单 | 工单号、计划数量、产品编码 |
| 制造费用 | 成本中心、费用类型、金额_元 |
| 期初余额 | 科目、借方、贷方 |

匹配率 ≥ 60% 才算识别成功；一个文件只归一类，取匹配列最多者。

## 2. 能力矩阵

| 能力 | 依赖 | 判定 |
|---|---|---|
| 报表级成本体检 | 成本构成 + 成本单 + 日报 + 废品回收 | 文件齐 → 可用 |
| 成本结构趋势 | 成本构成 | 可用 |
| 工单异常与自洽 | 成本单 | 可用 |
| 跨表勾稽 | 成本单 + 日报 + 废品回收 | 可用 |
| BOM 结构分析 | BOM | 可用 |
| 材料领用汇总 | 领料 | 可用 |
| 人工成本归集 | 报工 | 可用 |
| 材料差异（六项） | BOM + 领料 + 物料主数据 + 生产订单 | 缺文件或语义不通 → 不可用/部分 |
| 人工效率差异 | 报工 + 工艺路线 + 生产订单 | 缺标准工时 → 不可用 |
| 制造费用分配 | 制造费用 + 报工 | 缺费用明细 → 不可用 |
| 约当产量/在产 | 生产订单（计划数量、在产进度） | 缺字段 → 不可用 |

「部分可用」表示文件齐、但语义有缺口（例如领料是汇总码，对不上 BOM 叶子）。

## 3. 语义勾稽

| 检查 | 通过标准 | 不通过意味着 |
|---|---|---|
| 领料金额 vs 成本单材料 | 按工单一致 | 领料漏记/口径不同 |
| 人工成本 vs 成本单人工 | 按工单一致 | 报工与成本单脱节 |
| 废品回收 vs 日报 | 按季度一致 | 回收未入账或跨期 |
| BOM 物料 vs 领料编码 | 叶子级覆盖 | 领料太粗，无法做材料量差 |
| 单位成本 vs 分项合计 | 按工单一致 | 单位成本可能是标准价，或漏了废品损失 |

## 4. 怎么读结论

- **缺文件**：明确列出来，补导即可；
- **语义不通**：不是数据错，而是粒度/编码体系不匹配，需要主数据治理或换报表；
- **勾稽失败**：先修数据，再谈归因；
- **全部通过**：才能进入体检或六项差异。

样例（汽车零部件 9 张表）的结论是：报表级体检可用；六项差异、人工效率、费用分配、约当产量
都不可用——因为领料是 `RM-MIX-01` / `SF-MIX-01` 汇总码，BOM 叶子覆盖率 0/7，且缺标准价与计划数量。

## 5. 扩展

新增一种单据：在 `costcontrol/coverage.py` 的 `SCHEMAS` 里加一行（类型、标签、必需列）。
新增一种能力：在 `CAPABILITIES` 里加一行（能力名、依赖类型、语义阻塞项）。
不需要改解析代码——识别、缺失列、能力矩阵都是配置驱动的。

## 6. 边界

- 只检查结构与勾稽，不判断业务合理性；
- 识别基于表头，改名/翻译过的导出可能识别失败（会列在「未识别」里）；
- 不检查数值分布与异常值——那是 `--reports` 体检与 `--diagnose` 的事。
