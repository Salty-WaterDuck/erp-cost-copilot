# 成本还原与差异穿透

「成品单位成本 51.34，标准 48.85，超了 2.49 元」——这句话只是开始。

接下来一定会被追问两个问题：

1. **这 51.34 里，材料到底占多少？** 账面「直接材料」20,061.86 里混着半成品的加工费，不是真实的原材料消耗。
2. **这 2.49 元超支，该找谁？** 是总装车间，还是壶身组件工单？

成本还原回答第一个问题，差异穿透回答第二个。

---

## 1. 为什么账面「材料」不可信

逐步结转分步法下，成品领用半成品时按半成品的**完全成本**入账：

```text
2026-10-003  PO-1003 材料领用
  借 5001 生产成本     20,061.86
    贷 1403 原材料       2,632.50
    贷 1406 自制半成品  17,429.36   ← 壶身 9,406.53 + 底座 8,022.83
```

那 17,429.36 里，只有约 14,853 是真正的原材料（不锈钢、ABS、温控器、发热盘），剩下的约 2,577 是壶身/底座两个车间的**人工和制造费用**。

于是成本计算单上：

```text
PO-1003 材料 20,061.86（占 86.84%）/ 人工 1,504.00（6.51%）/ 费用 1,536.12（6.65%）
```

这个结构会让人误以为「材料是成本的绝对大头」，而实际上：

```text
还原后：材料 17,485.09（75.69%）/ 人工 2,700.64（11.69%）/ 费用 2,916.25（12.62%）
```

材料占比被半成品转入抬高了 **11.15 个百分点**。如果拿账面结构去和行业对标、去谈降本，方向会错。

## 2. 成本项目还原

### 算法

从成品工单出发，把完工成本拆成三段：

```text
完工成本 = 材料(账面) + 人工 + 制造费用
```

对其中每一笔「半成品转入」，找到本期生产该半成品的工单，按 `领用数量 / 完工数量` 的比例把上游工单的完工成本分下来，再对上游工单递归做同样的事，直到全部落到外购原材料。

```text
PO-1003（成品）
├── 壶身组件 9,406.53 → PO-1001 完工成本 14,527.88 × (450/695)
│   ├── 不锈钢板 7,318.50 → 原始材料
│   ├── 温控器   4,760.00 → 原始材料
│   ├── 螺丝       140.00 → 原始材料
│   ├── 人工     1,064.00 → 原始人工
│   └── 费用     1,245.38 → 原始制造费用
├── 底座组件 8,022.83 → PO-1002 完工成本 12,301.64 × (450/690)
│   └── ...
├── 电源线 1,957.50 → 原始材料
├── 彩盒     675.00 → 原始材料
├── 人工   1,504.00 → 原始人工
└── 费用   1,536.12 → 原始制造费用
```

### 精确性

- 每一层都按「完工部分」折算：`材料 × output/材料约当量`、`人工/费用 × output/加工约当量`，所以在产不会混进还原结果；
- 每层拆分后把尾差归入制造费用，保证 `还原材料 + 还原人工 + 还原费用 ≡ 完工成本`，测试逐单断言；
- 三层 BOM（成品 → 半成品 → 半成品 → 原材料）有专门测试覆盖。

### 一个容易踩的坑

半成品的「标准成本」必须是**完全成本**（材料 + 本工序加工费）。如果标准只滚材料，还原后的材料占比会和实际严重偏离，因为标准价与结转账不同口径。这一点在 `docs/cost-model.md` 的 2.2 节有说明。

## 3. 差异穿透

### 传导金额是精确的

成品领用半成品时：

```text
材料价差 = 领用数量 × (实际结转单价 − 标准成本)
```

这个金额就是上游工单传给下游的差异，不多不少。演示数据里：

```text
PO-1003 差异 1,117.68
├── 自身       461.62   （电源线涨价 67.50、加班/效率、车间费用）
└── 上游转入   656.05
    ├── PO-1001 壶身组件 450 件 → 680.13
    └── PO-1002 底座组件 450 件 → −24.08
```

### 上游差异构成按比例映射

只知道「壶身组件传下来 680.13」还不够，还要知道它是涨价、超耗还是效率造成的。做法是把上游工单的六项差异按比例缩放到 680.13：

```text
PO-1001 差异 953.48 → 分给 PO-1003 的 680.13（比例 0.7133）
  材料价差 388.50 × 0.7133 = 277.12
  材料量差 285.60 × 0.7133 = 203.72
  人工效率  84.00 × 0.7133 =  59.92
  费用耗费 105.38 × 0.7133 =  75.17
  费用效率  90.00 × 0.7133 =  64.20
  ────────────────────────────────────
  合计 680.13（尾差补给绝对值最大的分项）
```

**这是分摊，不是精确归因**，文档和输出里都会注明。可以精确的是「传下来多少钱」，不能精确的是「这笔钱在上游内部属于哪一类」——因为上游的差异是整张工单的，不会按领用批次拆分。

### 为什么不做无限递归

上游工单的「材料价差」里已经包含了它自己领用半成品带来的传导，所以展示一层就够：更深的层级已经聚合在「材料价差」这个分项里。无限展开只会得到一棵越来越难读的树。

## 4. 和「差异六项」的关系

| 视角 | 回答的问题 | 输出 |
|---|---|---|
| 差异六项 | 这张工单差在哪一类？ | 价差/量差/工资率/效率/耗费/费用效率 |
| 差异穿透 | 这张工单的差异是谁造成的？ | 自身 vs 上游转入，逐单列出 |
| 成本还原 | 成本的结构长什么样？ | 材料/人工/费用，剔除外购半成品 |

三者一起看，才是一张能拿去开成本分析会的表。

---

## 5. 边界

1. **只还原本期有工单的半成品。** 如果领用的是期初库存半成品，本期没有生产成本，就退回标准成本结转（系统会给 `TRANSFER-STD` 提示），还原时按标准成本结构拆分。
2. **上游差异构成是比例分摊**，已在上文注明；总额精确。
3. **不处理联产品/副产品**的联合成本还原。
4. **不还原跨期差异**：本期差异只在本期工单之间传导。
5. 多张工单生产同一半成品时，按各工单完工数量加权（与全月一次加权平均的结转口径一致）。

---

## 6. 怎么用

```bash
python -m costcontrol.cli --restore
```

输出两段：

- **成本还原表**：每张完工工单的账面三段 vs 还原三段，以及半成品转入金额；附产成品的成本结构变化。
- **差异穿透**：每张成品的总差异 = 自身 + 上游转入，并列出上游各工单的构成。

把它接进月度成本分析会，能直接回答三个问题：材料占比为什么虚高、超支该找哪个车间、降本应该先动哪一类成本。
